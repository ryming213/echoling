## 2. 项目概述

### 2.1 软件简介

「听言英语」是一款基于 Android 原生平台开发的英语听说训练应用。软件聚焦"通过视频/音频素材进行逐句精听、跟读、复述测试"这一核心训练闭环，配合本地化词典查询、闪卡式单词记忆等辅助功能，为英语学习者提供一套离线优先、零网络依赖的便携学习工具。

### 2.2 核心功能

| 功能模块 | 简要说明 |
|---|---|
| 课程导入 | 通过系统 SAF（Storage Access Framework）选择本地音视频素材，自动识别同名字幕文件 |
| 字幕解析 | 支持 SRT / ASS / LRC 三种主流字幕格式的解析与同步 |
| 跟读练习 | 泛听（自由播放）/ 精听（单句循环）/ 测试（跟读对比）三段式练习 |
| 跟读对比测试 | 用户按住录音，系统在本地将语音转写为文字后与原字幕逐词匹配对比（详见 §8.2） |
| 长按取词 | 长按字幕单词调出本地词典查询，支持音标、词性、翻译、例句显示，并可一键收藏至生词本 |
| 闪卡记单词 | 11 大词库（小学 / 初中 / 高中 / CET-4 / CET-6 / CET-8 / 考研 / 托福 / GRE / IELTS / BEC）的卡片式记忆 |
| 单词发音 | 基于系统 TTS 引擎朗读单词（多引擎自动 fallback） |
| 学习统计 | 按天统计学习时长、已学句子数、新增单词数；按月热力图可视化活跃度 |
| 权限使用说明 | 在 App 内集中声明权限用途与隐私承诺 |

### 2.3 软件特点

1. **100% 离线可用**：Vosk 离线识别模型（约 68 MB）已内置在 APK 内，运行时不再产生任何网络请求；词典数据全部打包在 APK 内。
2. **全 Kotlin 原生开发**：基于 Jetpack Compose + MVVM + Clean Architecture，不引入任何 Java 代码，不使用任何 XML 布局。
3. **跟读对比测试设计**：本软件的"复述/跟读测试"采用"语音识别 → 文本 → 与原文逐词对比"的方式实现（详见 §8.2），不引入任何打分、评分或发音质量评估机制。
4. **数据本地化**：所有用户学习数据存储于本地 Room 数据库，不上传任何用户数据到云端。

## 4. 需求分析

### 4.1 功能性需求

#### 4.1.1 课程管理

- 用户可导入本地的 mp4 / mkv / mp3 / wav 文件作为练习素材
- 系统自动在同目录下查找与媒体文件同名的 `.srt` / `.ass` / `.lrc` 字幕文件
- 若未找到同名字幕，提示用户手动选择字幕文件
- 导入完成后，课程卡片出现在"首页"列表中

#### 4.1.2 跟读练习

- 课程详情页展示课程元信息（标题、描述、难度、时长、句子数）
- 进入跟读练习后，提供三个 Tab：

| Tab | 名称 | 主要操作 |
|---|---|---|
| 泛听 | Listening | 自由播放；点击字幕条目跳到对应句播放 |
| 精听 | Speaking | 单句循环；可点单词隐藏/显示；可录音并回放 |
| 测试 | Testing | 按住麦克风录音 → 转写文字 → 与原字幕逐词对比 |

#### 4.1.3 跟读测试核心规则

> **重要设计声明**：
> 本软件的跟读测试采用"语音识别 → 文本 → 与原字幕逐词对比"的方式实现。
> 系统将用户说出的话转写为英文文本后，**通过词序匹配（详见 §8.2 WordMatcher 算法）将识别结果与原字幕逐词对比**，并在 UI 上以"绿底=匹配 / 红底=未匹配"的颜色块直观反馈每个单词的命中情况。
> 本系统**不包含任何打分、评分、发音质量评估机制**——测试结果仅为"通过 / 未通过"二元判定，外加按词展示的命中详情，不存在"本次复述得分 X 分"之类的评分概念。

#### 4.1.4 词典查询与生词本

- 用户在泛听 / 精听页面长按字幕单词，弹出"翻译 & 保存"对话框
- 对话框显示单词、音标、词性、翻译、例句（若有）
- 用户可一键保存至生词本，生词本独立持久化于 Room 表 `vocabulary`

#### 4.1.5 闪卡记单词

- 11 大词库以分类卡片形式展示在"记单词"主页
- 进入分类后展示闪卡（正方形卡片，点击触发 Y 轴 3D 翻转查看翻译）
- 用户点击"认识"或"不认识"后自动翻到下一张；进度自动持久化

### 4.2 非功能性需求

## 5. 系统架构设计

### 5.1 总体架构

软件采用 **Clean Architecture（整洁架构）+ MVVM** 模式，严格按"UI → ViewModel → UseCase → Repository → Data"的分层调用链，禁止跨层访问。

```
┌─────────────────────────────────────────────────────────────┐
│                       UI Layer (Compose)                     │
│  Screens · Components · Navigation (Pager + NavHost)        │
└────────────────────────┬────────────────────────────────────┘
                         │ collectAsState / 事件回调
┌────────────────────────┴────────────────────────────────────┐
│                    Presentation Layer                        │
│            ViewModels · UiState · StateFlow                 │
└────────────────────────┬────────────────────────────────────┘
                         │ 业务调用
┌────────────────────────┴────────────────────────────────────┐
│                      Domain Layer                            │
│    Models · UseCases · Repository Interfaces                │
└────────────────────────┬────────────────────────────────────┘
                         │ 接口实现
┌────────────────────────┴────────────────────────────────────┐
│                       Data Layer                             │
│    RepositoryImpls · DAOs · Room Entities · Datasources      │
└────────────────────────┬────────────────────────────────────┘
                         │ 第三方封装
┌────────────────────────┴────────────────────────────────────┐
│                    Core Modules                              │
│  Player(ExoPlayer) · Speech(Vosk) · Subtitle · TtsManager   │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 模块划分

软件代码按职责划分为 8 个顶层包：

| 包名 | 职责 | 关键文件 |
|---|---|---|
| `com.echoling.app` | 应用入口 | `EchoLingApplication.kt` |
| `com.echoling.app.presentation` | UI 层 | `MainActivity.kt`、`viewmodel/*`、`ui/*` |
| `com.echoling.app.domain` | 域模型层 | `model/*`、`repository/*`、`usecase/*` |
| `com.echoling.app.data` | 数据层 | `repository/*`（impl）、`local/db/*` |
| `com.echoling.app.player` | 播放引擎 | `AudioPlayer.kt`、`subtitle/*`、`TtsManager.kt` |
| `com.echoling.app.speech` | 语音处理 | `VoskSpeechRecognizer.kt`、`SttRecognizer.kt`、`WordMatcher.kt`、`WavRecorder.kt` |

### 5.3 依赖注入（Hilt）

- **应用入口**：`EchoLingApplication` 标注 `@HiltAndroidApp`
- **Activity**：`MainActivity` 标注 `@AndroidEntryPoint`
- **ViewModel**：标注 `@HiltViewModel`，构造器 `@Inject` 注入 UseCase
- **UseCase**：标注 `@Singleton` + `@Inject constructor`，自动注册，无需 Module
- **Repository 接口与实现**：在 `RepositoryModule` 用 `@Binds` 绑定
- **第三方封装**（AudioPlayer、VoskSpeechRecognizer 等）：标注 `@Singleton` + `@Inject constructor`，自动注册

### 5.4 协程与并发

- 所有 IO / CPU 密集操作均在 `Dispatchers.IO` 上执行
- ViewModel 通过 `viewModelScope` 管理生命周期内协程
- 状态通过 `StateFlow` / `SharedFlow` 暴露给 UI
- UI 通过 `collectAsState()` 订阅状态，事件回调反向触发 ViewModel 方法

### 5.5 导航架构

- **Tab 切换**：使用 `HorizontalPager`（4 个主 tab：首页 / 单词本 / 记单词 / 我的），支持左右滑动手势，原生方向感知动画

- **完整路由**：

| 路由 | 入口 |
|---|---|
| `tab_root` | Pager 内默认占位（透明 Box） |
| `course_detail/{courseId}` | 首页课程卡片点击 |
| `practice/{courseId}` | 课程详情页底部按钮 |
| `import` | 首页右下角 FAB |
| `statistics` | 首页统计按钮 / "我的" 入口 |
| `instructions` | "我的" 入口 |
| `permissions` | "我的" 权限说明入口 |
| `category_study/{categoryId}` | "记单词" 分类卡片点击 |

#### 6.6.2 `VoskSpeechRecognizer`

- `@Singleton`，封装 Vosk 0.3.45 离线 STT
- **模型来源**：Vosk 离线识别模型（约 68 MB）已**预置**在 APK `assets/models/` 目录中，首次启动时由 `ModelManager.ensureModelReady()` 从 assets 解压至内部存储（一次性 IO，之后复用）
- **完全离线**：模型内置后所有识别操作均在本地完成，无需任何网络请求
- `transcribeFile(wavPath: String): Result<String>`：
  - 校验 WAV 文件头（RIFF/WAVE、44 字节）
  - 创建 `Recognizer(model, 16000f)`
  - **关键修复**：循环调用 `acceptWaveForm` 直至返回 `false`（endpoint detected），每次返回 true 时调用 `recognizer.result` 读取已提交段，最后调 `recognizer.finalResult` 读取尾段，**累加所有段**（旧版只取尾段，会丢失句首段文本）
  - 解析返回 JSON，提取 `text` 字段

#### 6.6.4 `TtsManager`

- `@Singleton`，封装 Android `TextToSpeech`

## 8. 关键算法设计

### 8.1 跟读测试端到端流程

跟读测试的完整数据流如下：

```
用户按住麦克风
  ↓
WavRecorder.start() → 16kHz mono PCM WAV 文件落地
  ↓
用户松开麦克风
  ↓
VoskSpeechRecognizer.transcribeFile(wavPath)
  ├─ ModelManager.ensureModelReady()（首次时从 APK assets 解压部署 ~68MB 内置模型到内部存储）
  ├─ Recognizer 循环处理 WAV 数据
  │   - acceptWaveForm 每次返回 true → 取 recognizer.result 累加段文本
  │   - acceptWaveForm 返回 false → 取 recognizer.finalResult 取尾段
  │   - 全部段用空格 join → 得到完整识别文本
  └─ 返回 Result<String>（识别文本）
  ↓
WordMatcher.match(originalSubtitle, recognizedText)
  ├─ 双向 normalize：小写 + 去标点 + 按空白 split
  ├─ 空文本 → reason="empty_transcription"
  └─ 贪心多集对齐（详见 §8.2）→ MatchResult(passed, origMatched[], transMatched[], reason)
  ↓
PracticeViewModel 写入 SentenceEntity.isTested = true（仅当 passed=true 时）
  ↓
UI 更新：SttTestState.Transcribed / Passed / Failed
  ↓
TestingPage 渲染：每词命中块用绿/红背景区分
```

### 8.2 WordMatcher 词序匹配算法

#### 8.2.1 算法目标

将"原字幕英文文本"与"Vosk 转写得到的英文文本"逐词匹配，输出：
- `passed: Boolean` —— 全部原词都有对应转写词视为通过
- `origWords: List<String>` —— 原文本分词结果
- `transWords: List<String>` —— 转写文本分词结果
- `origMatched: BooleanArray` —— 每个原词是否被匹配（与 origWords 索引对齐）
- `transMatched: BooleanArray` —— 每个转写词是否被消费（与 transWords 索引对齐）
- `reason: String` —— `"ok"` / `"empty_transcription"` / `"wrong_word"`

#### 8.2.2 算法流程

**步骤 1：标准化**

```kotlin
fun normalize(s: String): List<String> =
    s.lowercase()
     .replace(NORMALIZE_REGEX, " ")    // 非字母数字的字符替换为空格
     .split(Regex("\\s+"))
     .filter { it.isNotEmpty() }
```

将大写转小写，标点替换为空格，按空白拆分为单词列表。

**步骤 2：空文本短路**

若 `transWords.isEmpty()`，直接返回 `MatchResult(passed=false, reason="empty_transcription")`，`origMatched` 全 false。

**步骤 3：贪心多集对齐**

```kotlin
val origMatched = BooleanArray(orig.size)
val transMatched = BooleanArray(trans.size)

for (i in orig.indices) {
    for (j in trans.indices) {
        if (!transMatched[j] && fuzzyEqual(orig[i], trans[j])) {
            origMatched[i] = true
            transMatched[j] = true
            break
        }
    }
}

val passed = origMatched.all { it }
```

对每个原词，按顺序查找第一个未被消费的、与之"模糊相等"的转写词。找到则双方都标记 matched；找不到则该原词未匹配。

**关键性质：position-independent（位置无关）**——一个原词是否被匹配只取决于"是否有转写词与之等价"，不取决于它们的位置顺序。这避免了"第一个词错了导致后续全错"的级联误判。

**步骤 4：模糊相等判定**

```kotlin
private fun fuzzyEqual(a: String, b: String): Boolean {
    if (a == b) return true
    if (a.length < 2 || b.length < 2) return false
    if ((a to b) in COMMON_ALTERNATES) return true
    if ((b to a) in COMMON_ALTERNATES) return true
    val threshold = when (maxOf(a.length, b.length)) {
        in 0..3 -> 0    // "to" "a" "I" 必须精确匹配
        in 4..5 -> 1    // "were" "have" 允许 1 编辑距离
        else -> 2       // 其它允许 2 编辑距离
    }
    if (threshold == 0) return false
    return levenshtein(a, b) <= threshold
}
```

支持 3 类等价：
1. **完全相等**
2. **常见交替形态**：`COMMON_ALTERNATES = {("were", "was"), ("got", "gotten"), ...}` —— 处理虚拟语气 / 美英差异等语义等价但编辑距离超阈值的情况
3. **长度缩放 Levenshtein 距离**：短词严格（0 编辑）、中等词 1 编辑、长词 2 编辑

#### 8.2.3 Levenshtein 实现

采用迭代两行动态规划，O(len(a) × len(b)) 时间、O(b) 空间。STT 转写单词通常短于 20 字符，O(n²) 完全可接受。

#### 8.2.4 测试结果展示

UI 层根据 `MatchResult` 渲染颜色块：
- `origMatched[i] == true` → 原词所在 chip 背景为绿色（命中）
- `origMatched[i] == false` → 原词所在 chip 背景为红色（未命中）
- `transMatched[j] == false` → 转写词所在 chip 背景显示为灰色（多余词）

### 8.3 SRT 字幕解析算法

```
逐行读取文本
  ↓
按空行 / 连续空行分割为段落
  ↓
对每个段落：
  ├─ 第一行：解析序号（整数）
  ├─ 第二行：解析时间戳 "HH:MM:SS,mmm --> HH:MM:SS,mmm"
  ├─ 第三行起：合并为 contentEn
  ├─ 若有第四行且以中文字符开头 → contentCn
  └─ 输出 Subtitle(index, startTimeMs, endTimeMs, contentEn, contentCn)
```

时间戳解析：`HH:MM:SS,mmm` → `h*3600000 + m*60000 + s*1000 + mmm`。

### 8.4 闪卡 Y 轴 3D 翻转动画

```kotlin
@Composable
fun FlashCard(isFlipped: Boolean, front: @Composable () -> Unit, back: @Composable () -> Unit) {
    val rotation by animateFloatAsState(
        targetValue = if (isFlipped) 180f else 0f,
        animationSpec = tween(durationMillis = 420)
    )
    val showBack = rotation > 90f  // 90° 时 swap 正反面

    Box(
        modifier = Modifier
            .graphicsLayer {
                rotationY = rotation
                cameraDistance = 12f * density  // 防止 >120° 鱼眼变形
            }
            .aspectRatio(1f)  // 强制正方形
    ) {
        if (!showBack) front() else back()
    }
}
```

**关键参数**：
- `cameraDistance = 12f * density` —— Compose 默认相机距离太近，>120° 时变鱼眼，×12 保持 180° 自然透视
- `showBack = rotation > 90f` —— 90° 时卡片边缘对镜头、不可见，此时交换正反面
- 反面组件预先旋转 180°（`rotationY = 180f`），外层再旋转后字是正的

### 8.5 11 词库的嵌套 / 扁平 schema 自动嗅探

部分词库 JSON 是 4 层嵌套（百度翻译导出格式），部分是 2 层扁平（自定义格式）。自动嗅探逻辑：

```kotlin
fun loadAsset(assetName: String): List<DictEntry> {
    val firstLine = assets.open(assetName).bufferedReader().readLine()
    return if (firstLine.contains("\"wordRank\"")) {
        // 嵌套路径：headWord → content.word.content.trans[]
        parseNested(assets.open(assetName))
    } else {
        // 扁平路径：直接 List<DictEntry>
        parseFlat(assets.open(assetName))
    }
}
```

通过读取首行是否含 `"wordRank"` 字段判定 schema，避免全文件扫描（4.6 MB 文件首行 sniff 仅 O(64) 字节）。

- 启动期不加载任何词库详细数据，仅加载 manifest（4 KB）

### 10.2 内存管理

- 词典 JSON 解析在 `Dispatchers.IO` 上执行，UI 线程零阻塞
- 词库按 category 懒加载，未访问的 category 不解析
- ExoPlayer 单例，所有页面共享一个实例
- Pager 4 个 page 常驻渲染（offscreen 也保留 composition），sub-page 单独的 NavHost 实例

### 10.3 16 KB 页大小对齐（Android 15+）

Android 15+ 强制要求 native lib 和 zip entry 按 16 KB 对齐。本项目通过三层 hook 实现：

1. **ELF 内部**：`patchNativeLibsFor16KB` hook 在 `packageDebug.doFirst` 跑，把 `stripped_native_libs/` 下每个 `.so` 的 `PT_LOAD.p_align` 从 4096 改成 16384
2. **Zip 外部（.so）**：`repackApk16kb` hook 在 `packageDebug.doLast` 用 `0xD935` extra block 把每个未压缩 `.so` 的 data offset 推到 16384 倍数
3. **Zip 外部（resources.arsc）**：同上，把 STORED entry（含 resources.arsc）推到 4 字节倍数（Android R+ 要求）
4. **重新签名**：用 apksigner v1+v2+v3 重签
5. **删除 stale `.idsig`**：AGP 后写的 v4 `.idsig` 与新签名不一致会引发 `INSTALL_PARSE_FAILED_NO_CERTIFICATES`，必须删除

### 10.4 隐私设计

- **AndroidManifest 不声明 `INTERNET` 权限**——所有网络功能刻意不可用，从根上杜绝任何数据外传可能
- **Vosk 离线识别模型内置**——约 68 MB 模型直接打包在 APK `assets/models/` 中，首次启动解压至内部存储；运行时所有识别完全本地完成
- **词典数据打包在 APK assets**——词典查询完全本地
- **学习数据存本地 Room**——用户进度不上传
- **SAF 选择媒体**——通过 `OpenDocument` 获取单次读写权限，不需要 `READ_MEDIA_*` 永久权限
- **「我的」页面提供权限使用说明子页** —— 在 App 内集中声明每个权限的用途

### 10.5 错误处理与降级

| 错误场景 | 降级策略 |
|---|---|
| Vosk 模型加载失败 | 显示"模型加载失败"卡片，用户可重试或重装 |
| TTS 引擎全部不可用 | 喇叭按钮可见但点击后显示 snackbar 提示 |
| 字幕文件不存在 | 导入时弹出提示，用户可手动选择字幕 |
| 媒体文件损坏 | ExoPlayer 内部错误处理，UI 显示播放错误 |
| 词典查询无结果 | 对话框显示"未找到该单词"，不弹错 |

### 10.6 并发与生命周期

- 所有协程绑定到 `viewModelScope`，ViewModel 销毁时自动取消
- `SharedFlow` + `extraBufferCapacity` 保护 STT 事件不丢
- Pager 状态用 `rememberPagerState`（内部 `rememberSaveable`），旋转屏幕后保持当前 tab

### 11.1 单元测试

- **`WordMatcherTest`** —— 验证词序匹配算法的关键 case：
  - 完全相同文本 → passed=true
  - 单个拼写差异（Levenshtein 容差内）→ passed=true
  - 单词遗漏 → passed=false，对应 origMatched=false
  - 词序变化（"If I were you" vs "If I was you"）→ passed=true（COMMON_ALTERNATES 命中）
  - 空转写 → reason="empty_transcription"
  - 标点差异 → passed=true（normalize 后等价）
